## Что изменено
- Шаги атомарные: открытие «Личные данные», XSS/пусто, валидное сохранение, проверка шапки.
- SQL-проверка БД (`SELECT * FROM navi_stage1.site_users…`) убрана из обязательных шагов smoke сайта — вынесена в опциональный шаг (доступ к БД есть не всегда).

- Скриншоты: placeholder `screenshots/cabinet/`.

## Описание
Проверка сохранения изменений регистрационных данных и базовой валидации формы «Личные данные» / смены пароля.

## Предусловия
1. Иметь аккаунт на сайте (NAVI2E-1).
2. Авторизоваться на `https://www.{СТЕНД}.navi.inlearno.info`.
3. Открыть кабинет пользователя.
4. Запомнить текущие ФИО и email.
5. Подготовить новые валидные Имя/Фамилию/Отчество/Телефон (email не менять без необходимости, чтобы не потерять доступ).

## Шаги

### Шаг 1
**Действие:**
Нажать «Личные данные».

**Ожидаемый результат:**
Отображаются три блока:
1. **РЕГИСТРАЦИОННЫЕ ДАННЫЕ:** ИМЯ*, ФАМИЛИЯ*, ОТЧЕСТВО, МУНИЦИПАЛИТЕТ*, ТЕЛЕФОН*, ПОЧТА*; текст «Изменения вступят в силу, после того как вы нажмете кнопку «Сохранить изменения»»; кнопки «СОХРАНИТЬ ИЗМЕНЕНИЯ», «ОТМЕНИТЬ ИЗМЕНЕНИЯ».
2. **АВТОРИЗАЦИЯ:** «Введите новый пароль», «Введите новый пароль еще раз», кнопка «ИЗМЕНИТЬ ПАРОЛЬ».
3. **ЗАЯВЛЕНИЯ:** «ПОДАТЬ ЗАЯВЛЕНИЕ НА УДАЛЕНИЕ ПЕРСОНАЛЬНЫХ ДАННЫХ», «ПОДАТЬ ЗАЯВЛЕНИЕ НА ИЗМЕНЕНИЕ ПЕРСОНАЛЬНЫХ ДАННЫХ».

![step1](../screenshots/cabinet/user-personal-data.png)

### Шаг 2
**Действие:**
Очистить обязательные поля «ИМЯ» и «ФАМИЛИЯ», нажать «СОХРАНИТЬ ИЗМЕНЕНИЯ».

**Ожидаемый результат:**
Изменения **не** сохраняются. Под обязательными полями — сообщения об ошибке. ФИО в шапке не меняется.

![step2](../screenshots/cabinet/user-personal-data-empty-validation.png)

### Шаг 3
**Действие:**
В «ИМЯ» ввести `<img src=x onerror=alert(1)>`, в «ТЕЛЕФОН» — строку без маски (`abc`). Нажать «СОХРАНИТЬ ИЗМЕНЕНИЯ».

**Ожидаемый результат:**
Скрипт/обработчик **не** выполняется. Телефон не проходит маску. Данные не сохраняются, отображаются сообщения об ошибке.

![step3](../screenshots/cabinet/user-personal-data-xss-phone.png)

### Шаг 4
**Действие:**
Ввести валидные изменения: Имя, Фамилия, Отчество, Телефон (из таблицы). Нажать «СОХРАНИТЬ ИЗМЕНЕНИЯ».

**Ожидаемый результат:**
Поля с зелёной рамкой успешной валидации. Под блоком — зелёное уведомление «Изменения сохранены!». В шапке (и/или в углу кабинета) отображается новое ФИО.

![step4](../screenshots/cabinet/user-personal-data-saved.png)

### Шаг 5
**Действие:**
В блоке «АВТОРИЗАЦИЯ» ввести новый пароль короче 8 символов и отличное значение в поле подтверждения. Нажать «ИЗМЕНИТЬ ПАРОЛЬ».

**Ожидаемый результат:**
Пароль не меняется. Отображаются ошибки: длина/сложность и/или несовпадение паролей.

![step5](../screenshots/cabinet/user-password-mismatch.png)

## Опционально (не входит в smoke UI)
Проверка БД при наличии доступа: `site_users` по email аккаунта — поля имени/телефона соответствуют шагу 4.

## Общий ожидаемый результат
Валидные изменения регистрационных данных сохраняются и видны в UI. Пустые обязательные поля, XSS и невалидный телефон/пароль отклоняются с понятными сообщениями.

## Критерии приемки
- [ ] Все три блока «Личные данные» отображаются с актуальными названиями кнопок.
- [ ] Пустые обязательные поля не сохраняются.
- [ ] XSS не исполняется.
- [ ] Успешное сохранение показывает «Изменения сохранены!» и обновляет ФИО в UI.
- [ ] Невалидная смена пароля отклоняется.
