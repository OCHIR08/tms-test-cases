# ⚠️ CRITICAL RULES FOR TEST CASE GENERATION

**Формат и структура:**
- Использовать ТОЛЬКО секции: Описание, Предусловия, Шаги, Общий ожидаемый результат.
- ЗАПРЕЩЕНО добавлять секции: "Связанные тест-кейсы", "Примечания", "Параметры (data-driven)".

**Стиль написания шагов (ВАЖНО):**
- Шаги должны быть ОБЩИМИ и высокоуровневыми. 
- ЗАПРЕЩЕНО указывать конкретные тестовые данные в шагах (никаких "test+001@example.com", "Иванов Иван", "Test1234").
- ЗАПРЕЩЕНО указывать полные URL-адреса (использовать "на публичный сайт", "в личный кабинет").
- Вместо перечисления полей писать: "Заполнить обязательные поля валидными тестовыми данными".
- Вместо перечисления текстов чекбоксов писать: "Отметить чекбоксы согласий".

**Скриншоты:**
- Добавлять ссылку на скриншот в конце каждого шага в формате: `![stepN](../screenshots/[module]/[screenshot_name].png)`
- Имена скриншотов должны соответствовать реальной структуре папок проекта.

**Пример идеального шага:**
**Действие:** Заполнить все обязательные поля формы валидными тестовыми данными и отметить чекбоксы согласий.
**Ожидаемый результат:** Кнопка отправки формы становится активной.
